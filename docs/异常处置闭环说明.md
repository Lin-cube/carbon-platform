# 异常处置闭环说明

> 打通过程：**异常发现 → 诊断 → 人工处理 → 记录回写 → 历史追溯 → AI 参考**

## 一、状态机

```
未处理 ──→ 处理中 ──→ 已处理 ──→ 待复检 ──→ 已处理
   └──────────────→ 已忽略
```

| 状态 | `handled` | 说明 |
|---|---|---|
| 未处理 | 0 | 默认值 |
| 处理中 | 0 | 已介入排查 |
| 已处理 | **1** | 已闭环，**必须填写备注** |
| 已忽略 | **1** | 判定为误报/无需处理，**必须填写备注** |
| 待复检 | **1** | 措施已下发，等待复检（复检能力本期只预留字段） |

`handled` 由 `handle_status` 派生，**原有异常率统计口径完全不变**（异常率仍基于 `fact_energy_hourly.anomaly_flag`）。

## 二、接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/anomalies/{id}` | 登录用户 | 异常详情 + 处理信息 + 处理历史 |
| GET | `/api/anomalies/{id}/history` | 登录用户 | 处理历史（时间正序） |
| POST | `/api/anomalies/{id}/handle` | **admin / operator** | 回写处理状态与备注 |
| GET | `/api/anomalies/handled` | 登录用户 | 历史处置案例（只读，供 AI/复盘） |
| GET | `/api/anomalies/stats` | 登录用户 | 按状态统计 |

### POST /api/anomalies/{id}/handle

```json
{
  "status": "已处理",
  "note": "已核查为冷凝器结垢，安排 11 月清洗，清洗前临时降低负荷",
  "version": 0
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `status` | 是 | 未处理 / 处理中 / 已处理 / 已忽略 / 待复检 |
| `note` | 是（已处理/已忽略） | 最长 512 字 |
| `version` | 否 | 乐观锁；传了则版本不符返回 409 |

### 错误码

| 场景 | HTTP | code |
|---|---|---|
| 备注为空却标记已处理 | 200 | 400 |
| 重复处理（状态与备注均未变） | 200 | 400 |
| 并发更新（版本号过期） | 200 | **409** |
| 只读用户（viewer）调用 | **403** | 403 |
| 事件不存在 | 200 | 404 |

## 三、AI 与人工的边界

- 小E **没有任何写工具**，`getAnomalyHandleHistory` 是只读的；
- 要求 AI「标记已处理」时，它会明确拒绝并说明需人工确认；
- System Prompt 已写入红线：不得声称已完成标记、不得把历史处置记录当作当前结论。

## 四、数据表

| 表/字段 | 说明 |
|---|---|
| `fact_anomaly_event.handle_status` | 处置状态 |
| `handle_by` / `handle_at` | 处理人与时间 |
| `handle_version` | 乐观锁版本 |
| `verify_status` / `verify_at` | 复检预留（本期未启用） |
| `anomaly_handle_log` | 操作审计：from → to、备注、操作人、时间 |

## 五、前端

「异常诊断」页新增：
- 列表「处理状态」「处理信息」列 + 状态筛选
- 行内「处理异常」按钮（仅 admin/operator 可见）
- 抽屉：异常详情 → 状态选择 → 备注 → 提交 → 处理历史时间线
