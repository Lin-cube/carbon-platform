## 二、是否主流？

### 结论：**是主流，且是 2025 年国内政企/竞赛项目的主流组合。**

逐项对照：

| 技术 | 主流度 | 说明 |
|---|---|---|
| Vue 3 + TypeScript + Vite | ⭐⭐⭐⭐⭐ | 国内前端绝对主流（Vue 官方推荐组合） |
| Element Plus | ⭐⭐⭐⭐⭐ | Vue3 生态使用率最高的 UI 库 |
| Pinia | ⭐⭐⭐⭐⭐ | Vue 官方推荐的状态管理（Vuex 已被官方标记为维护模式） |
| ECharts | ⭐⭐⭐⭐⭐ | 国内数据可视化事实标准（Apache 顶级项目） |
| Three.js | ⭐⭐⭐⭐⭐ | WebGL 3D 事实标准 |
| Spring Boot 3 + JDK 21 | ⭐⭐⭐⭐⭐ | 国内 Java 后端主流；JDK 21 是当前 LTS |
| MyBatis-Plus | ⭐⭐⭐⭐⭐ | 国内 Java 持久层使用率第一（高于 JPA） |
| JWT + Spring Security | ⭐⭐⭐⭐⭐ | 前后端分离项目的标准做法 |
| MySQL 8 | ⭐⭐⭐⭐⭐ | 国内业务库事实标准 |
| pandas / Parquet | ⭐⭐⭐⭐⭐ | 数据分析标准栈 |
| springdoc-openapi | ⭐⭐⭐⭐⭐ | Spring Boot 3 的 OpenAPI 3 标准实现 |
| EasyExcel | ⭐⭐⭐⭐ | 国内 Java 报表导出主流（阿里出品） |

### 值得说明的国内特色选择

1. **MyBatis-Plus 而非 JPA** —— 国际项目多用 JPA/Hibernate，但国内因为要做大量复杂聚合查询（报表场景），MyBatis + 手写 SQL 更可控。本项目 30 个接口里有相当一部分是聚合查询，这个选择是对的。
2. **Element Plus 而非 Ant Design Vue** —— 两者都是一线选择，Element Plus 与 Vue 3 官方生态更贴近。
3. **不用若依（RuoYi）** —— 申报表提及若依，但若依官方版基于 Spring Boot 2.x / JDK 8，与本机 JDK 21 兼容成本高；且其代码生成、定时任务、多数据源等模块本项目用不到。自研轻量脚手架只需实现 RBAC + 审计两张表 + 一个切面（约 200 行），比裁剪若依更快。**该决策已在技术方案文档中说明。**

### 一个需要如实说明的取舍

**springdoc Swagger UI 替代了 Knife4j。** Knife4j 提供中文界面、更友好的调试体验，是国内容器项目常见选择。但：

- Knife4j 最新版 **4.5.0**（2024 年发布后再无更新）捆绑 **springdoc 2.3.0**
- springdoc 2.3.0 面向 Spring Framework 6.0/6.1，而 **Spring Boot 3.5.6 带的是 Spring Framework 6.2**
- 结果：运行时报 `java.lang.NoSuchMethodError`，`/v3/api-docs` 返回 **500**，接口文档实际不可用

**这是本次审计发现的真实故障**，此前文档中"接口文档可访问"的说法不成立（`/doc.html` 返回 200 只是静态页，底层 API 数据是 500）。已切换为 springdoc 官方 2.9.0，实测 `/v3/api-docs` 收录 **30 个接口**、`/swagger-ui/index.html` 正常。

> 教训：第三方 starter 与 Spring Boot 主版本的兼容性必须**运行时验证**，不能只看"能编译通过"。

## 三、是否冗余？

### 结论：**清理前有 9 处冗余，已全部清理。清理后无冗余。**

审计方法：对每个声明的依赖，用 grep 核对源码中的实际引用；引用数为 0 的判定为冗余。

### 3.1 已清理清单（均有实测依据）

| 位置 | 冗余项 | 判定依据 | 处置 |
|---|---|---|---|
| 后端 | `hutool-core` 5.8.34 | 源码零引用（`BeanUtil` / `StrUtil` 均为 0 次） | ✅ 移除 |
| 后端 | `spring-boot-starter-cache` | `@EnableCaching` 已开启但 **`@Cacheable` 零使用** | ✅ 移除 |
| 后端 | `caffeine` | 随上项一起引入，无使用点 | ✅ 移除 |
| 后端 | `@EnableCaching` 注解 | 缓存无使用点，开着只是徒增启动开销与误解 | ✅ 移除 |
| 管道 | `scipy` | 异常检测用 numpy + pandas 的滚动分位数实现，未 import scipy | ✅ 移除 |
| 管道 | `openpyxl` | 管道只导出 CSV/Parquet/JSON；Excel 由后端 EasyExcel 负责 | ✅ 移除 |
| 管道 | `fastapi` / `uvicorn` | AI 服务由角色 B 的独立 Python 工程实现，不属于本管道 | ✅ 移除（改在交接文档中说明） |
| 前端 | `dayjs` | 源码零引用（日期格式化用原生 + ECharts 内置） | ✅ 移除 |
| 前端 | `unplugin-auto-import` / `unplugin-vue-components` | 装了但 **`vite.config.ts` 里完全没配置**（配置数 = 0） | ✅ 移除 |

### 3.2 特别说明：`knife4j` 不是"冗余"，是"故障"

审计时 `knife4j` 也显示"Java 源码零引用"（因为只用它的 starter，不直接 import 类），但它确实在运行时提供 UI。
不过实测发现它的 UI 数据源 `/v3/api-docs` **报 500**，属于**功能性故障**而非冗余，因此处置方式是"**替换**"而不是"删除"——换成 springdoc 2.9.0。

> 这个案例说明：**"源码零引用"不足以判定依赖可删**。注解驱动 / starter 驱动的依赖必须做运行验证。

## 四、仍在但"看着像冗余"的依赖（保留理由）

审计要防止误删，以下几项经核对后**保留**：

| 依赖 | 为什么看着像冗余 | 保留理由 |
|---|---|---|
| `spring-boot-starter-actuator` | 源码只有 1 处引用 | **运行时实测可用**：`/actuator/health` 返回 db UP，`/actuator/metrics` 返回 200。演示时可用作"服务健康"证据 |
| `mybatis-plus-jsqlparser` | 只有 1 处引用 | 3.5.9 起分页拦截器被拆分到该模块，**不引入则分页功能编译失败**（已实测） |
| `easyexcel` | 只有 2 处引用 | 报表导出功能的核心实现，且它顺带提供 POI（`BorderStyle` 等样式类） |
| `lombok` | 编译期依赖，运行时不打包 | 大幅减少样板代码（65 个 Java 文件） |
| `vue-tsc` | 只在 `pnpm build` 时执行 | 类型检查门禁；注意 `build:only` 脚本**不含**类型检查，若要严格门禁需用 `pnpm build` |
| `@types/three` | 类型包 | Three.js 无内置类型，缺失则 IDE 与类型检查报错 |

## 五、技术复杂度是否匹配项目量级？

**代码规模**（实测）：

| 层 | 文件 | 行数 |
|---|---|---|
| 后端 Java | 65 | 6,067 |
| 前端 Vue/TS | 19 | 4,593 |
| 数据管道 Python | 9 | 2,618 |
| SQL | 1 | 433 |
| **合计** | **94** | **13,711** |

**评估**：13.7k 行支撑「599 万条数据集 + 30 个接口 + 8 个页面 + 3D 模型 + 五步导入向导 + 4 张预聚合表」，**复杂度与规模匹配，没有过度设计**。

但有两处**刻意的额外投入**，需要说明其正当性：

1. **可插拔 AI 客户端（Mock + HTTP 双实现）** —— 看似多余，实为**解耦手段**。因为 AI 模块由队友负责且进度不可控，若无此抽象，前端与问答链路会被阻塞。这是应对真实协作约束的设计，不是过度设计。
2. **两级降级（LLM → 规则引擎）** —— 看似重复实现了两遍字段映射，实为**稳定性要求**。演示现场网络不可控，规则引擎保证"永不失败"。实测规则引擎在留出集上 50%、LLM 路径 60%，两者互补。

## 七、结论

| 问题 | 回答 |
|---|---|
| 技术栈是什么？ | 见 §一：Vue3 + TS + Vite + Element Plus + ECharts + Three.js ／ Spring Boot 3.5 + JDK 21 + MyBatis-Plus + MySQL 8.4 ／ Python + pandas + Parquet |
| 是主流做法吗？ | **是。** 每一层都是当前国内主流选型，且相互配套（Vue3 官方推荐组合、Spring Boot 3 + JDK 21 LTS、MyBatis-Plus 国内第一）。唯一非主流处是**用 springdoc 替代 Knife4j**，但这是被兼容性故障逼出来的正确决定。 |
| 技术冗余吗？ | **清理前是（9 处），清理后不是。** 冗余集中在"声明了但没用"的依赖，已逐项用 grep 核实并移除。另需注意：`knife4j` 看着像冗余实为故障，已替换而非删除。 |

**审计方法可复现**：所有判定均基于源码引用计数 + 运行时端点实测，命令记录在各节中。
