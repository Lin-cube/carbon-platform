# 每次怎么启动（速查）

> 只需记住一条命令：`./scripts/start-all.sh daemon`
> 遇到「代码跑不起来」，90% 是 MySQL 没启动，先看这里。

---

## 一、两种场景，两个命令

| 你的目的 | 命令 | 说明 |
|---|---|---|
| **我要用系统 / 演示** | `./scripts/start-all.sh daemon` | 起全部 4 个服务，关终端也不停 |
| **我要在 VSCode / IDEA 里写后端代码** | `./scripts/start-all.sh dev` | 只起 MySQL + 前端 + RAG，**8080 留空给 IDE** |

两条命令的执行位置都在：

```bash
cd <项目根目录>
```

---

## 二、日常使用（推荐）：`daemon`

```bash
cd <项目根目录>
./scripts/start-all.sh daemon
```

输出应该长这样：

```
[密钥] 已加载 secrets/local.env（LLM provider=deepseek）
[常驻] 通过 launchctl 注册服务（关闭终端不影响）
  ✅ MySQL   已就绪 (端口 3307)
  ✅ 后端     已就绪 (端口 8080)
  ✅ 前端     已就绪 (端口 5173)
  ✅ RAG 服务 已就绪 (端口 8000)

服务状态:
  ✅ MySQL   3307
  ✅ 后端     8080
  ✅ 前端     5173
  ✅ RAG     8000
```

然后浏览器打开 **http://127.0.0.1:5173**，用 `admin / admin123` 登录。

**为什么用 `daemon` 而不是 `-d`**：
`daemon` 用 macOS 的 `launchctl` 托管，进程归属系统，**关闭终端、关掉 VSCode 都不影响**。
`-d` 用 nohup，终端退出后进程可能被系统回收。

---

## 三、写后端代码：`dev`

```bash
cd <项目根目录>
./scripts/start-all.sh dev
```

输出会提示：

```
  ✅ 8080 空闲，可以在 IDE 中启动后端了

服务状态:
  ✅ MySQL   3307
  ⭕ 后端     8080 未运行     ← 故意留空
  ✅ 前端     5173
  ✅ RAG     8000

下一步：VSCode 打开 CarbonPlatformApplication.java → 点 ▶ 运行
```

然后：
1. VSCode 打开 `backend/src/main/java/com/carbon/platform/CarbonPlatformApplication.java`
2. 点 `main` 左边的 **▶**（或 F5）
3. 用项目里配好的启动项「启动后端 CarbonPlatformApplication」

> 从 IDE 启动时，「AI 批量规划导入」会降级为规则引擎（因为 `.vscode/launch.json` 里没放密钥）。
> 其它功能都正常，包括「小E」知识问答（那是 RAG 服务在调 DeepSeek）。
> 需要完整 LLM 能力就用 `daemon` 模式。

---

## 四、停止

```bash
cd <项目根目录>
./scripts/start-all.sh stop
```

会停掉 4 个服务并释放端口。**从 IDE 启动的后端不会被这条命令停掉**，需要你在 IDE 里点停止。

---

## 五、查看状态

```bash
./scripts/start-all.sh status
```

四个 ✅ 就正常。有任何 ⭕ 就重新 `daemon` 一次。

---

## 六、常见问题

### 报 `Communications link failure`、`CJCommunicationsException`

**MySQL 没启动。** 这是最常见的问题（机器重启/休眠后 MySQL 不会自动起来）。

```bash
./scripts/start-all.sh daemon     # 会先启动 MySQL
```

只想单独启数据库：
```bash
./scripts/mysql.sh start
```

### 报 `Web server failed to start. Port 8080 was already in use`

8080 被占了，通常是：
- 另一个后端实例还在跑 → `./scripts/start-all.sh stop`
- 或你先跑了 `daemon` 又想从 IDE 启动 → 先 `stop`，再 `dev`

查是谁占的：
```bash
lsof -nP -iTCP:8080 -sTCP:LISTEN
```

### 报 `Unresolved compilation problem` 或 `ClassFormatError`

**在旧进程还在运行时编译了。** 正确顺序：

```bash
launchctl remove carbon-backend 2>/dev/null
pkill -f "spring-boot:run"; sleep 3
cd backend && mvn -s ../scripts/maven-settings.xml clean compile
./scripts/start-all.sh daemon
```

### 前端打不开（5173）

```bash
tail -20 .logs/frontend.err.log
```

常见原因是 pnpm 路径问题（已在脚本里改成绝对路径）。

### 端口全部正常但页面报错

看后端日志：
```bash
tail -50 .logs/backend.log
```

## 七、服务一览

| 服务 | 端口 | 作用 | 挂了会怎样 |
|---|---|---|---|
| MySQL | 3307 | 599 万行能耗数据 | **后端启动失败**（最常见） |
| 后端 | 8080 | 30 个 API | 前端报错、页面空白 |
| 前端 | 5173 | 8 个页面 | 打不开页面 |
| RAG | 8000 | 8,921 条知识语料 | 「小E」知识类问题降级为纯检索 |

日志都在 `carbon-platform/.logs/`：

| 文件 | 内容 |
|---|---|
| `backend.log` | 后端启动与运行日志 |
| `backend.err.log` | 后端错误输出 |
| `frontend.log` / `frontend.err.log` | 前端 |
| `rag.log` / `rag.err.log` | RAG 服务 |

---

## 八、一句话总结

```bash
cd <项目根目录>

./scripts/start-all.sh daemon    # 用系统 / 演示
./scripts/start-all.sh dev       # 写后端代码（后端留给 IDE）
./scripts/start-all.sh status    # 看状态
./scripts/start-all.sh stop      # 停止
```

**记住 `daemon` 和 `dev` 两个词就够了。**
