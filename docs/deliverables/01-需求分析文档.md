**项目名称**：碳能智控运维平台
**申报单位**：郑州西亚斯学院 工学部科大讯飞人工智能学院
**项目导师**：席宏昌
**项目周期**：7—9 周
**文档版本**：v1.0

---

## 一、项目背景与需求来源

### 1.1 政策与行业背景

全球气候变化已成为国际社会面临的重大挑战。我国明确提出 **2030 年前碳达峰、2060 年前碳中和**的战略目标。建筑行业是碳排放的核心源头之一，其**运行阶段**（采暖、制冷、照明、设备运行等）碳排放占全国碳排放总量的 **20% 以上**，是落实"双碳"目标的关键领域。

赛题合作支持单位**中建八局第二建设有限公司**为世界 500 强中国建筑股份有限公司子公司，深耕绿色低碳建筑与智慧建筑领域，自主研发"擎翼数字中枢"智慧运维平台，已在临沂大学、临朐县人民医院等项目落地。

### 1.2 需求来源

本项目需求来源于**真实校企合作场景**（申报表"项目来源：☑校企合作"），由项目导师席宏昌提出，聚焦建筑能源管理实际业务的三大痛点。

## 二、核心需求（问题定义）

### 2.1 业务现状与痛点

依据申报表描述，当前建筑运维存在以下问题：

| # | 痛点 | 具体表现 | 可量化影响 |
|---|---|---|---|
| ① | **运维决策缺乏智能赋能** | 故障诊断慢、准确率低 | 专业人员单次运维响应平均 **5 分钟**，非专业人员需 **30 分钟至数天** |
| ② | **知识资产难以传承** | 隐性经验无标准化沉淀机制 | "传帮带"困境突出 |
| ③ | **数据驱动智能化分析缺失** | 能耗数据停留在静态展示与简单统计 | 缺乏 AI 深度挖掘与智能预测 |
| ④ | **数据查询与报表效率低下** | 多源查询繁琐、报表生成冗长 | 数据割裂发生率超 **60%**，导致能效损失 **20%-30%** |

现有做法为**人工经验判断 + 传统阈值告警**，缺乏 AI 辅助分析与智能决策能力。

### 2.2 需求转化为系统能力

上述业务痛点需转化为以下系统能力：

| 痛点 | 系统能力需求 | 对应交付模块 |
|---|---|---|
| ④ 数据分散、查询低效 | 多源数据统一接入、标准化治理、多条件精准查询 | ① 能耗数据导入与治理 |
| ③ 数据止于静态展示 | 多维统计分析与可视化监控 | ② 实时监控与可视化看板 |
| ① 诊断慢、依赖人工 | 异常自动识别 + 归因诊断 + 处置建议 | ② 看板告警 + ③ AI 智慧问答与诊断 |
| ② 知识传承难 | 领域知识库 + 自然语言问答 | ③ AI 智慧问答与诊断 |

## 三、目标用户与使用场景

### 3.1 目标用户

| 用户角色 | 关注点 | 典型操作 |
|---|---|---|
| **建筑能源管理人员** | 全局能耗态势、能效对标、报表上报 | 查看看板、导出能耗报表 |
| **运维技术人员** | 异常定位、故障原因、处置措施 | 接收告警、触发诊断、查看优化建议 |
| **建筑管理决策人员** | 能耗评级、碳排放趋势、节能潜力 | 查看建筑评级分布、碳排统计 |

### 3.2 使用场景

申报表明确列出的场景包括：能耗数据导入与治理、实时监控与异常告警、AI 智慧问答诊断能耗异常、能耗评估与节能规划、自动化报表生成。系统可嵌入中建八局二公司"擎翼数字中枢"，也可在校园、医院、商业综合体等场景推广。

**典型场景走查**

**场景 A：新接入园区的数据治理**
园区管理人员拿到一份历史能耗 Excel 台账（列名不统一、含单位后缀、存在负值与重复行）→ 通过五步向导上传 → 系统自动识别列并给出字段映射建议 → 选择清洗规则 → 预览确认 → 导入落库并留下审计记录。

**场景 B：发现能耗异常并定位原因**
运维人员在看板看到某建筑异常率偏高 → 进入异常诊断查看异常事件列表 → 点击诊断，系统给出"异常时段 vs 正常时段"的对比证据（室外温度 +7.2℃、人员密度 +1.5 人/100㎡、COP -0.33、供回水温差 -0.42℃）→ 生成归因假设与处置建议 → 运维人员现场复核后处置。

**场景 C：自然语言问答**
决策人员直接提问"Eagle 园区 2016 年下半年用电量是多少？"→ 系统识别意图、调用统计能力、返回带数据证据与知识库引用的回答。

**场景 D：节能规划与报表**
管理人员选择时间范围 → 系统输出时段汇总、尖峰平谷分时占比、异常统计 → 一键导出 5 个工作表的 Excel 报表。

## 四、功能范围

### 4.1 本轮交付范围（3 项核心任务）

| 任务 | 功能点 |
|---|---|
| **① 能耗数据导入与治理** | 支持 CSV/JSON/Excel 多源接入；五步向导式流程（数据源选择 → 字段映射 → 清洗规则 → 预览导入 → 审计留痕）；AI 批量规划导入实现自动分类与字段映射 |
| **② 实时监控与可视化看板** | 3D 园区模型展示；能耗趋势图；异常告警推送；建筑/楼栋/房间级状态监控与能耗评级 |
| **③ AI 智慧问答与诊断** | "小E"AI 助手支持自然语言问答、能耗异常诊断、自动化报表生成；基于 MCP 工具 + RAG 知识库实现专业问答与运维建议闭环 |

### 4.2 查询统计能力（赛题手册要求）

- 基于 MCP 协议开发数据接入与查询接口，支持按**建筑、时间、监测参数**等条件精准查询
- 至少实现 **3 类核心统计分析**：时段汇总、COP 计算、数据异常分析
- 支持至少 **2 种可视化图表**展示，可自动生成并导出统计报表

### 4.3 本轮明确不做（申报表第 6 项）

| # | 不做内容 | 原因 |
|---|---|---|
| ① | 移动端 APP 开发 | 本轮聚焦 Web 端完整闭环 |
| ② | 建筑设备（BACnet/Modbus）实时物联网直连采集 | 需现场硬件配合与协议调试，超出 7-9 周周期 |
| ③ | 多园区/集团级跨园区能源对标 | 依赖更多园区数据与对标基准体系 |
| ④ | 碳排放交易与碳资产管理模块 | 属碳市场业务，非本次能源运维范围 |
| ⑤ | 能耗预测模型训练与部署平台 | 本轮重点为查询统计与智能运维 |
| ⑥ | 用户付费与计费系统 | 非校园/校企合作场景需求 |

以上功能在后续迭代中视需求规划。

## 五、技术难点与解决方案

| # | 技术难点 | 难点本质 | 解决方案 | 验证结果 |
|---|---|---|---|---|
| 1 | **数据语义不一致** | 开源数据集表计数值语义不明（累计读数 vs 区间消耗量），判断错误会导致全部统计失真 | 通过序列形态分析确认语义，并与官方 notebook 交叉验证 | 确认 BDG2 为**每小时区间消耗量**，直接 SUM 即可（单调递增比例仅 0.484） |
| 2 | **表计计量口径混乱** | 同一园区同时存在建筑级分表与冷站级总表，量级差异达数量级 | 逐表计可信度校验（覆盖率 + 读数有效性 + 能耗强度上限），辅以官方 `metadata.eui` 做单位校准 | 全电建筑表计推算 EUI 与官方值比值 **1.083**，证明单位正确；剔除量级失真表计 |
| 3 | **近零负荷建筑误报** | 假期教学楼等长期低负荷建筑基线≈0，任何用电都会被判异常 | 引入**显著性下限**：被标记读数须同时超过该建筑自身 P75 分位 | 该类建筑异常率 **12.98% → 5.88%**，与其他区间持平 |
| 4 | **异常检测误报率难达标** | 建筑电耗近似对数正态、右尾很重，固定 3σ 阈值在正常数据上就有 12.2% 误报 | 采用**分层基线（星期几×小时）+ 残差分位数阈值**，阈值随建筑自适应 | 召回率 **98.68%**、误报率 **3.29%**，达到 ≥90% / ≤10% 指标 |
| 5 | **聚合查询响应超时** | 600 万行事实表上做条件求和需 1.1–1.7 秒，叠加其他子查询后接口超过 2 秒验收线 | 建立预聚合表（`agg_building_daily` / `agg_building_monthly` / `agg_anomaly_daily`），看板与报表一律查预聚合表 | 异常分析接口 **2.263s → 0.257s**，16 个接口全部 ≤ 2s |
| 6 | **仿真字段被误当实测值** | 供回水温度、COP、人员密度在开源数据中不存在，需推算补全，存在合规风险 | 建立**数据来源三态标注**（实测/推算/仿真/标注），在数据字典、接口返回、前端徽章三处贯穿标注 | 申报表第 17 条"风险边界说明"要求得到满足 |
| 7 | **AI 模块未就绪时全栈阻塞** | AI/算法角色（队友）的 RAG/MCP 服务开发周期不确定，会阻塞前端联调 | **Mock 优先**设计：`carbon.ai.mode=mock\|http` 双实现，Mock 由后端真实统计能力驱动 | 前端与问答链路现已可完整联调，切换成本为零 |

## 七、数据与合规边界

依据申报表第六部分：

| 项 | 说明 |
|---|---|
| **数据与信息类型** | ☑公开/模拟数据 ☑一般内部资料 |
| **数据来源与授权** | ① 公开开源数据集 BDG2（Building Data Genome Project 2，**CC-BY 4.0** 许可，可自由使用并署名）；② 行业规范与运维手册等公开资料 |
| **脱敏措施** | BDG2 本身为已脱敏的公开学术数据集，建筑名称均为化名（如 `Eagle_education_Peter`），不含真实地址与企业内部信息 |
| **保存期限** | 项目结束后保留一学期 |
| **访问范围** | 仅项目组成员 |
| **不得采集** | 真实建筑能耗原始数据 |
| **不得展示** | 中建八局二公司内部业务流程细节 |
| **不得接入** | 企业生产环境数据库 |
| **不得输出** | 未脱敏的真实能耗数据 |

### 专业风险与人工复核措施（申报表第 17 条）

| 风险环节 | 人工复核措施 | 系统落实 |
|---|---|---|
| AI 生成的能耗异常诊断与运维建议可能存在偏差 | AI 诊断结果需运维人员确认后方可执行 | 所有诊断与建议响应均带 `needsManualReview: true` 字段；建议附免责声明 |
| AI 批量规划导入的字段映射可能不准确 | AI 批量导入需用户预览确认后执行 | 五步向导强制"预览导入"步骤，用户确认后才落库 |
| 算法误报 | 采用"模型偏差 + 规则约束"双重判定机制 | 分层基线（模型偏差）+ 物理规则与显著性下限（规则约束） |
| AI 生成的报表初稿 | 需人工编辑确认后导出 | 报表导出为原始统计数据，AI 解读文字单独标注 |

> **AI 输出不直接作为最终决策依据。**
