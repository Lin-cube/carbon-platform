# 香港服务器 + 宝塔 + 域名 部署方案

> 面向：即将购买 2 核 4G 香港服务器、用宝塔面板、绑定域名部署本项目。
> 本文给出**选型结论、下单前必查项、分步部署流程、以及会踩的坑**。

---

## 一、选型结论：买 2 核 4G（48 元/月那款）

| 对比项 | 2核2G（33元） | **2核4G（48元）** | 差异 |
|---|---|---|---|
| 内存 | 2 GB | **4 GB** | 差 15 元/月 |
| 带宽 | 5M 上传 / 10M 下载 | **8M 上传 / 15M 下载** | 首屏 1.19s vs **0.74s** |
| 硬盘 | 30–250 GB | 30–250 GB | 同 |
| 月价 | 33 元 | 48 元 | **+15 元（+45%）** |

### 为什么不选 2G

**内存预算实测推算**：

| 项目 | 占用 | 来源 |
|---|---|---|
| 后端 JVM（`-Xmx384m`） | 274 MB | **本机实测** |
| Python RAG 服务 | 65 MB | **本机实测** |
| 宝塔面板本体 | ~180 MB | 经验估算 |
| 宝塔 · Nginx | ~25 MB | 经验估算 |
| 宝塔 · MySQL 8.0（buffer pool 256M） | ~450 MB | 经验估算 |
| 宝塔 · 监控与计划任务 | ~50 MB | 经验估算 |
| Linux 系统 | ~220 MB | 经验估算 |
| **合计** | **≈ 1264 MB** | |

**2G 机器：占用 62%，看似够用。但问题是剩下的 784MB 要留给什么？**

留给 **Linux 页缓存**（page cache）。MySQL 读数据时，热点数据要能被页缓存住才有性能。
本项目的 `fact_energy_hourly` 表有 **2.5 GB**，2G 机器上根本无法缓存，
每次查询都要打磁盘 → 查询变慢，CPU 再被拖累。

**4G 机器**：剩余 2.8GB 页缓存，足够把热点数据（预聚合表 100MB + 索引）全缓存住，查询快得多。

### 为什么带宽也要选 8M

首屏资源 gzip 后 759 KB：

| 带宽 | 理论速度 | 首屏首次加载 |
|---|---|---|
| 5M 上传 | 0.62 MB/s | **1.19 秒** |
| 8M 上传 | 1.00 MB/s | **0.74 秒** |

注意：这里的"上传"是**从服务器到用户的出站流量**（服务器视角的上传），
也就是你打开网页时下载资源的速度。5M 也能用，但首屏多等 0.45 秒，
答辩演示时这点差距会被放大感知。

### 结论

> **买 48 元的 2 核 4G。** 一年多花 180 元，换来：
> ① 不用担心 OOM 和 swap；② MySQL 有足够页缓存；③ 首屏快 1.6 倍。

**省钱的正确方式不是降配置，而是"按量付费"**——如果只是答辩用几天，
2核4G 按量付费可能总共就十几元。

## 二、下单前必须确认的 5 件事

### ① 是否含独立公网 IPv4

香港服务器一般自带，但要确认。**没有公网 IP 就无法绑定域名**。

### ② 硬盘是 30GB 还是可调

页面写「30–250 GB」通常是**可选的**。建议选 **50GB 以上**：

| 项 | 占用 |
|---|---|
| MySQL 数据（表 2.5GB + 索引） | ~3 GB |
| 宝塔面板 + 环境 | ~1.5 GB |
| Python venv | ~0.5 GB |
| 系统 + 日志 | ~2 GB |
| **小计** | **~7 GB** |
| 数据库备份（2 份） | ~5 GB |
| 余量 | — |

30GB 够用但没余量，**50GB 更从容**。若加钱不多，选 50GB。

### ③ 流量是"不限"还是"流量包"

部分香港服务器标注「不限流量」，部分限每月 1000GB。
本项目演示级用量极小（首屏 759KB × 几百次访问 = 几百 MB），基本不会超。
但仍要确认**不是按流量后付费**，避免意外扣费。

### ④ 系统镜像选 Ubuntu 22.04 / 24.04 LTS

- **不要选 CentOS 7**（已 EOL，MySQL 8 装不上）
- Ubuntu LTS 对宝塔兼容性最好
- 如果只有 Debian / AlmaLinux，选 Debian 12 也可以

### ⑤ 香港服务器**不需要 ICP 备案**

这是选香港的最大好处：

| 地区 | 备案要求 | 域名直接访问 |
|---|---|---|
| 中国大陆 | 必须 ICP 备案（2~3 周） | 不备案会被拦截 |
| **香港 / 海外** | **无需备案** | ✅ 可直接用域名 |

所以你买域名后**当天就能绑上用**，不用等备案。这是正确的选择。

## 三、部署流程（宝塔 + 域名）

### 阶段 0：服务器初始化

```bash
# SSH 登录（用服务商给的 root 密码或密钥）
ssh root@你的服务器IP

# 更新系统
apt update && apt upgrade -y

# 装常用工具
apt install -y curl wget git unzip vim
```

### 阶段 1：安装宝塔面板

```bash
# 官方安装脚本（Ubuntu/Debian）
wget -O install.sh https://download.bt.cn/install/install-ubuntu_6.0.sh
bash install.sh ed8484bec
```

安装完会输出：

```
==================================================================
外网面板地址: https://你的IP:随机端口/随机路径
内网面板地址: ...
username: xxxxxxxx
password: xxxxxxxxxxxx
==================================================================
```

**⚠️ 立刻做三件事**：

1. **保存好面板地址、账号、密码**（只显示一次）
2. **记录那个随机端口**（不是默认 8888，宝塔新版会随机）
3. 浏览器打开时会有安全警告（自签名证书），点「高级 → 继续访问」

### 阶段 2：宝塔里装软件（关键：选对版本）

登录宝塔 → 首次进入会提示「推荐安装套件」，**不要一键安装**，手动选：

| 软件 | 版本 | 是否必装 | 说明 |
|---|---|---|---|
| **Nginx** | 1.24+ | ✅ 必装 | 托管前端 + 反向代理 |
| **MySQL** | **8.0**（**绝对不能选 5.7**） | ✅ 必装 | 项目用了窗口函数、CTE、分区表 |
| PHP | — | ❌ **不装** | 本项目没有 PHP |
| phpMyAdmin | — | 🔶 可选 | 图形化管理数据库，占内存，可后装 |
| Redis | — | ❌ **不装** | 本项目不需要（见 `09-服务器配置评估.md` §四） |
| Docker | — | ❌ **不装** | 本项目不用容器 |
| 防火墙 | — | ✅ 建议 | 见阶段 6 |

**为什么 MySQL 必须是 8.0**：

```sql
-- 项目实际用到的 MySQL 8.0 特性（5.7 不支持）
WITH ordered AS (...)              -- CTE，5.7 不支持
LAG(ts) OVER (PARTITION BY ...)    -- 窗口函数，5.7 不支持
```
实测确认：`data-pipeline/scripts/07_load_to_mysql.py` 里的异常事件分组用了
`LAG()` 与 `SUM() OVER()`，**MySQL 5.7 会直接报语法错误**。

### 阶段 3：上传代码

三种方式，选一种：

**方式 A：Git（推荐，后续更新方便）**

```bash
# 服务器上
cd /www/wwwroot
git clone 你的仓库地址 carbon-platform
```

**方式 B：宝塔文件管理器上传**

把本地项目打包（**排除 node_modules / target / .venv / .mysql**）：

```bash
# 本机执行
cd <项目根目录>
tar --exclude='node_modules' --exclude='target' --exclude='.venv' \
    --exclude='.mysql' --exclude='dist' --exclude='.git' \
    -czf carbon-platform.tar.gz .
```

然后宝塔「文件」→ 上传到 `/www/wwwroot/carbon-platform` → 在线解压。

**方式 C：scp**

```bash
# 本机执行
scp carbon-platform.tar.gz root@你的服务器IP:/www/wwwroot/
```

> ⚠️ **`.gitignore` 里的 `secrets/` 目录不要上传到公开仓库**。
> 服务器上单独创建 `secrets/local.env` 写密钥（见阶段 5）。

### 阶段 4：装运行环境

#### 4.1 JDK 21（后端需要）

apt install -y openjdk-21-jdk
java -version    # 应显示 21.x
```

若 apt 源里没有 21：

echo "deb https://packages.adoptium.net/artifactory/deb $(awk -F= '/^VERSION_CODENAME/{print$2}' /etc/os-release) main" > /etc/apt/sources.list.d/adoptium.list
apt update && apt install -y temurin-21-jdk
```

#### 4.2 Maven（构建后端）

```bash
apt install -y maven
mvn -v
```

> 也可以在**本机构建好 jar 再上传**，省服务器资源：
> ```bash
> # 本机
> cd backend && mvn -s ../scripts/maven-settings.xml clean package -DskipTests
> scp target/carbon-platform-backend-1.0.0.jar root@IP:/www/wwwroot/carbon/
> ```

#### 4.3 Python 3.12+（RAG 服务）

```bash
apt install -y python3 python3-pip python3-venv
cd /www/wwwroot/carbon-platform
python3 -m venv .venv
.venv/bin/pip install -i https://pypi.tuna.tsinghua.edu.cn/simple \
  pandas numpy pyarrow sqlalchemy pymysql jieba rank_bm25 scikit-learn scipy \

```

#### 4.4 Node.js（仅构建前端时用）

```bash
# 用 NodeSource 源装 Node 20 LTS
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs
npm install -g pnpm
```

> **构建完前端就可以卸载 Node**，运行时不占内存。
> 或者在本机构建好 `dist/` 再上传（推荐，省服务器 300MB 内存峰值）。

### 阶段 5：配置与初始化

#### 5.1 创建密钥文件

```bash
mkdir -p /www/wwwroot/carbon-platform/secrets
cat > /www/wwwroot/carbon-platform/secrets/local.env <<'EOF'
export CARBON_AI_MODE=hybrid
export CARBON_LLM_PROVIDER=deepseek
export CARBON_LLM_KEY=你的DeepSeek密钥
export CARBON_LLM_BASE=https://api.deepseek.com
export CARBON_LLM_MODEL=deepseek-chat
export CARBON_LLM_MAX_TOKENS=500
EOF
chmod 700 /www/wwwroot/carbon-platform/secrets
chmod 600 /www/wwwroot/carbon-platform/secrets/local.env
```

#### 5.2 建库与导入数据

```bash
# 建库（用宝塔的 MySQL 8.0）
mysql -u root -p -e "CREATE DATABASE carbon_energy DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_0900_ai_ci;"

# 建表
mysql -u root -p carbon_energy < data-pipeline/sql/01_schema.sql

# 导入数据（599 万行，约 5~10 分钟）
cd /www/wwwroot/carbon-platform
.venv/bin/python data-pipeline/scripts/07_load_to_mysql.py
```

> ⚠️ **导入前先调小 MySQL 内存**（宝塔默认 buffer pool 可能给到 1G）：
> 宝塔 → 数据库 → 配置修改 → `innodb_buffer_pool_size = 512M`

#### 5.3 构建 RAG 索引

```bash
cd /www/wwwroot/carbon-platform
.venv/bin/python rag-service/src/build_index.py
```

> 需要 `sikong_knowledge_base.txt` 在项目上级目录。如果没上传，跳过这步，
> RAG 会只有自建语料（9 条），知识问答能力下降但不报错。

#### 5.4 构建前端

```bash
cd frontend
pnpm install
pnpm run build          # 产出 dist/
```

### 阶段 6：配置开机自启（不用宝塔的"Java项目"功能）

宝塔的 Java 项目管理器有时会有坑（版本冲突、日志路径混乱）。
**用 systemd 更透明可控**。

#### 6.1 后端服务

```bash
cat > /etc/systemd/system/carbon-backend.service <<'EOF'
[Unit]
Description=Carbon Platform Backend
After=network.target mysqld.service

[Service]
Type=simple
User=root
WorkingDirectory=/www/wwwroot/carbon-platform/backend
EnvironmentFile=/www/wwwroot/carbon-platform/secrets/local.env
ExecStart=/usr/bin/java -Xmx512m -XX:+UseSerialGC \
  -XX:MaxMetaspaceSize=160m \
  -jar /www/wwwroot/carbon-platform/backend/target/carbon-platform-backend-1.0.0.jar
Restart=always
RestartSec=10
StandardOutput=append:/www/wwwlogs/carbon-backend.log
StandardError=append:/www/wwwlogs/carbon-backend.err.log

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now carbon-backend
systemctl status carbon-backend
```

> `EnvironmentFile` 会自动加载 `secrets/local.env`，**注意该文件里要写成
> `KEY=value` 形式**（去掉 `export` 前缀），否则 systemd 解析失败：
> ```bash
> # 生成 systemd 兼容版本
> sed 's/^export //' secrets/local.env > secrets/systemd.env
> ```
> 然后 `EnvironmentFile` 指向 `systemd.env`。

#### 6.2 RAG 服务

```bash
cat > /etc/systemd/system/carbon-rag.service <<'EOF'
[Unit]
Description=Carbon RAG Service
After=network.target carbon-backend.service

[Service]
Type=simple
User=root
WorkingDirectory=/www/wwwroot/carbon-platform/rag-service/src
EnvironmentFile=/www/wwwroot/carbon-platform/secrets/systemd.env
ExecStart=/www/wwwroot/carbon-platform/.venv/bin/python -m uvicorn \
  app:app --host 127.0.0.1 --port 8000 --workers 1
Restart=always
RestartSec=10
StandardOutput=append:/www/wwwlogs/carbon-rag.log
StandardError=append:/www/wwwlogs/carbon-rag.err.log

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now carbon-rag
```

> **`--workers 1` 必须**：索引在内存里，多 worker 会复制多份，4G 也扛不住。

### 阶段 7：宝塔配置站点 + 域名 + SSL

#### 7.1 添加站点

宝塔 → 网站 → 添加站点：

| 字段 | 填什么 |
|---|---|
| 域名 | `你的域名.com`（可同时填 `www.你的域名.com`） |
| 根目录 | `/www/wwwroot/carbon-platform/frontend/dist` |
| FTP | 不创建 |
| 数据库 | 不创建（已手动建） |
| PHP 版本 | **纯静态** |

#### 7.2 配置 Nginx 反向代理

站点设置 → 配置文件，替换为：

```nginx
server {
    listen 80;
    server_name 你的域名.com www.你的域名.com;
    root /www/wwwroot/carbon-platform/frontend/dist;
    index index.html;

    # Vue Router history 模式必须
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # AI 问答最长 3 秒，超时给足
        proxy_read_timeout 120s;
        proxy_connect_timeout 10s;
    }

    # 静态资源缓存（首屏资源带 hash，可长期缓存）
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # gzip 压缩（首屏从 2.9MB 降到 759KB）
    gzip on;
    gzip_min_length 1k;
    gzip_comp_level 5;
    gzip_types text/plain text/css application/json application/javascript
               application/x-javascript text/xml application/xml image/svg+xml;
    gzip_vary on;

    access_log /www/wwwlogs/carbon-access.log;
    error_log  /www/wwwlogs/carbon-error.log;
}
```

#### 7.3 域名解析

到你买域名的服务商（阿里云/腾讯云/Cloudflare 等）添加 DNS 记录：

| 类型 | 主机记录 | 记录值 | TTL |
|---|---|---|---|
| A | `@` | 你的服务器公网 IP | 600 |
| A | `www` | 你的服务器公网 IP | 600 |

> 香港服务器**无需备案**，解析生效后（几分钟到几小时）即可访问。

#### 7.4 申请免费 SSL（HTTPS）

宝塔 → 网站 → 你的站点 → SSL → **Let's Encrypt** → 申请 → 勾选「强制 HTTPS」。

> Let's Encrypt 免费、90 天自动续期，宝塔会配好定时任务。
> 申请前确保域名已解析到本服务器，否则验证会失败。

### 阶段 8：开放端口与安全加固

#### 8.1 防火墙（宝塔 → 安全）

只开必要的端口：

| 端口 | 用途 | 是否必须 |
|---|---|---|
| 80 | HTTP | ✅ |
| 443 | HTTPS | ✅ |
| 宝塔面板随机端口 | 面板访问 | ✅（改到非默认端口） |
| 22 | SSH | ✅（建议限制来源 IP） |
| **8080** | 后端 API | ❌ **不要对外开放**（走 nginx 反代） |
| **8000** | RAG 服务 | ❌ **不要对外开放** |
| **3306** | MySQL | ❌ **绝对不要对外开放** |

**这是最容易犯的错**：把 8080/3306 暴露到公网，被扫描到就是事故。

#### 8.2 宝塔面板安全（三件事必做）

1. **改面板端口**：面板设置 → 面板端口 → 改成 5 位随机数（如 38291）
2. **改管理员账号密码**：用强密码（16 位以上，含大小写数字符号）
3. **开启面板 SSL** + **绑定域名访问**（若有第二个域名）

> 宝塔面板历史上出过安全问题，公网暴露 + 弱密码 = 被入侵。
> 如果只在部署时用面板，**部署完可以停掉面板服务**：
> ```bash
> bt stop        # 停止面板（不影响网站）
> bt start       # 需要时再启
> ```

#### 8.3 数据库安全

```bash
# 改 root 密码（宝塔会给随机密码，去「数据库」页看）
# 确认 root 只允许本地连接
mysql -u root -p -e "SELECT user, host FROM mysql.user;"
# 应看到 root 的 host 是 localhost，不是 %
```

## 五、会踩的坑（按出现概率排序）

| # | 坑 | 症状 | 解决 |
|---|---|---|---|
| 1 | **MySQL 选成 5.7** | 导入数据报 `LAG is not supported` | 宝塔里卸载 5.7，装 8.0 |
| 2 | 端口 8080/3306 暴露公网 | 被扫描、数据库被删 | 防火墙只开 80/443 |
| 3 | 宝塔面板默认端口 + 弱密码 | 面板被爆破 | 改端口、强密码、不用时 `bt stop` |
| 4 | 前端 404（刷新页面白屏） | 访问 `/dashboard` 报 404 | nginx 加 `try_files $uri $uri/ /index.html` |
| 5 | 未开 gzip | 首屏加载 2.9MB 很慢 | nginx 加 gzip 配置（降到 759KB） |
| 6 | `secrets/local.env` 带 `export` | systemd 报 `Ignoring invalid environment assignment` | 生成 `sed 's/^export //'` 的版本 |
| 7 | RAG 起多个 worker | 内存瞬间翻倍 | `--workers 1` |
| 8 | Python 版本太低 | `pyarrow` 装不上 | Ubuntu 22.04 自带 3.10 够用；若报错用 `deadsnakes` 源装 3.12 |
| 9 | 时区不对 | 日志时间差 8 小时 | `timedatectl set-timezone Asia/Shanghai` |
| 10 | 磁盘满 | MySQL 起不来 | 关 binlog（`skip-log-bin`），清 `/www/wwwlogs/` 旧日志 |

## 七、一句话总结

> **买 48 元的 2 核 4G。** 2G 技术上能跑（约 1.26GB），但留给 MySQL 页缓存的空间太少，
> 查询会变慢，且宝塔栈内存波动时容易触发 OOM。
>
> 香港服务器**不用备案**，买完域名当天就能绑。宝塔里**MySQL 必须选 8.0**，
> **不要装 PHP / Redis / Docker**，它们只会白占内存。
>
> 后端和 RAG 用 **systemd** 托管比用宝塔的 Java 项目管理器更可控。
