# DeepSeek 和知识库分别负责什么

> 回答这个问题：**「我配了 DeepSeek API，它是干什么的？知识库以外的问题，DeepSeek 会自己答，还是会瞎编？」**

---

## 一、一句话回答

> **DeepSeek 是「嘴」，知识库是「脑子」。**
>
> DeepSeek 不负责查资料，只负责把检索到的资料**组织成人话**。
> 知识库里没有的内容，系统**直接拒答**，不会让 DeepSeek 用它的通用知识顶上。

---

## 二、三个引擎的分工

系统里其实有**三个**回答来源，不是一个：

```
用户提问
   │
   ├─ ① 数据类问题 ──→ 本地统计引擎 ──→ 查 MySQL → 返回真实数值
   │    "Eagle 园区 2016 年用电量多少"        （大模型完全不参与）
   │
   ├─ ② 知识类问题 ──→ RAG 检索 ──→ 找到知识库片段 ──→ DeepSeek 组织成答案
   │    "离心机喘振怎么处理"                              （大模型只做表达）
   │
   └─ ③ 知识库未覆盖 ──→ 相关度低于阈值 ──→ 直接拒答
        "怎么做红烧肉"                        （大模型都不调用）
```

### 实测确认

| 问题 | 走的引擎 | 回答来源 |
|---|---|---|
| 统计 Eagle 园区 2016 年用电量 | **本地统计** | 数据库真实数值 |
| 2016 年能耗异常率是多少 | **本地统计** | 数据库真实数值 |
| 离心机喘振怎么处理 | **RAG 知识库** | 知识库原文 + DeepSeek 组织 |
| 什么是小温差大流量 | **RAG 知识库** | 知识库原文 + DeepSeek 组织 |
| 怎么做红烧肉 | **拒答** | 「知识库中未找到」 |

---

## 三、DeepSeek 的具体职责

### 它做的事

拿到 3~5 条检索到的知识片段后，负责：

1. **归纳整理**：把片段里的要点按逻辑重排（成因 → 危害 → 处置）；
2. **去冗余**：不重复引用同一条；
3. **加出处**：每段后面标 `[来源：CHL-004]`；
4. **控制长度**：500 字以内（也是为了让响应时间可控）；
5. **遵守约束**：遇到片段标了「需核实」的内容，必须一并说明。

### 它不做的事

1. **不查数据库**——它拿不到 MySQL 的数据；
2. **不决定检索什么**——检索是 BM25 + 向量在做，DeepSeek 只拿结果；
3. **不补充片段之外的事实**——系统提示词明确禁止；
4. **不回答知识库外的内容**——低于阈值直接不调用它。

### 打个比方

> 想象一个**只给你念资料、不许自由发挥的助手**：
> - 你问他"喘振怎么处理"，他先翻资料，翻到了就照资料给你讲，并告诉你翻的是哪一页；
> - 翻不到，他就说"资料里没有"，**不会凭自己的想法编一套**。
>
> DeepSeek 就是这个"念资料的助手"。资料（知识库）决定了它能不能答、答得对不对。

---

## 四、知识库外的问题会怎样（这是你最关心的）

### 结论：**拒答，不会瞎编。**

我做了两道防线：

### 第一道：相关度阈值（确定性，不依赖模型）

检索永远会返回 top-k 条（BM25 算法特性），即使毫不相关。
所以我在调用 DeepSeek **之前**就判断：最高相关度低于 **2.5 分** → 直接拒答。

实测分数分布（这就是阈值的依据）：

| 问题类别 | 示例 | 检索得分 |
|---|---|---|
| **知识库覆盖** | 离心机喘振、小温差大流量、COP 下降 | **2.70 ~ 4.00** |
| 建筑相关但语料没有 | 光伏板清洗、电梯能耗、数据中心 PUE | 0.94 ~ 2.15 |
| 完全无关 | 今天天气、红烧肉、写诗、Python | 0.55 ~ 2.11 |

覆盖类最低 2.70，未覆盖类最高 2.15，**中间有 0.55 的间隔**，取 2.5 作分界。

### 第二道：系统提示词（兜底）

即使通过了阈值，提示词里也明确要求：

> 只能依据【检索到的知识片段】回答，不得使用你自己的常识补充具体数值；
> 若片段不足以回答，明确说"知识库中未找到相关内容"。

### 实际表现

| 问题 | 结果 |
|---|---|
| 今天天气怎么样 | `mode=refused-low-relevance`，最高分 1.00，**引用 0 条** |
| 怎么做红烧肉 | `mode=refused-low-relevance`，最高分 2.11，**引用 0 条** |
| 光伏板怎么清洗 | `mode=refused-low-relevance`，最高分 1.34 |
| 数据中心的 PUE 怎么算 | `mode=refused-low-relevance`，最高分 2.15 |

拒答时的回答长这样：

> 知识库中未找到与该问题相关的内容，因此不做回答。
> （最高相关度 2.11 分，低于拒答阈值 2.5。本知识库目前只覆盖建筑能源运维与设计规范领域。）
> 如果这确实是建筑能源相关问题，可能是语料尚未收录，建议补充相关资料；
> 如果与本项目领域无关，我无法回答——**不会用通用知识替代检索结果**。

**注意**：`citations` 返回 0 条。之前会返回 5 条无关引用，容易误导用户以为"有依据"，现在已改为空。

## 五、为什么要加这道阈值（改之前的问题）

**改之前的行为**：检索总是返回 5 条，然后靠 DeepSeek 自觉说"没找到"。

问题在于：
1. 这**依赖模型服从性**。换成较弱的模型，可能照片段硬编一段看似合理的回答；
2. 会返回 5 条毫不相关的引用，用户看到"有出处"会误以为可信；
3. 置信度还给到了 0.5（现在给 0.1）。

**改之后**：拒答是代码逻辑决定的，与模型无关。即使把 DeepSeek 换成任何模型，行为都一样。

> 这是一条重要经验：**安全边界要写在代码里，不要指望模型自觉。**

## 六、那 DeepSeek 到底值不值得配

### 值得，因为它在「知识库覆盖范围内」的作用不可替代

对比一下同一问题在两种模式下的输出：

**没有 DeepSeek（纯检索）**：
```
【1】小温差大流量综合症：成因与危害
来源：本项目自建语料 HVAC-002
【现象】冷冻水系统供回水温差明显小于设计值...
【成因】1. 末端盘管选型偏大或水阀常开...
（直接贴原文，600 字）
```

**有 DeepSeek（RAG 生成）**：
```
小温差大流量是指冷冻水系统供回水温差明显小于设计值，
同时循环流量大于设计流量。典型表现：设计温差 5℃，实际仅 1.5~2.5℃。
主要成因包括末端选型偏大、水力失衡、旁通阀常开、水泵定频等。
危害：水泵电耗上升（功率与流量三次方相关）、冷机效率下降。
排查顺序：先核对温差 → 再查阀门 → 再测各环路流量。
[来源：HVAC-002]
```

**差别**：后者有结构、有取舍、能直接读。前者是"给你一堆资料自己看"。

### 但如果只是演示"能查到资料"，不配 DeepSeek 也能跑

代码里保留了完整降级链：DeepSeek 不可用 → 自动回退到"纯检索回答"（返回原文 + 出处）。
功能不中断，只是回答不够精炼。

## 七、几个你会遇到的边界

| 场景 | 行为 | 说明 |
|---|---|---|
| 问数据但参数不全（如没说时间范围） | 本地统计按默认区间算 | 不会拒答 |
| 问知识但语料只有部分相关 | 返回部分覆盖的内容 + 说明局限 | 阈值之上就答 |
| 问到规范具体数值 | 答原理 + 标"需核实" | 不编造条文 |
| 问到项目数据集本身 | 答数据字典与已知限制 | 有专门语料 |
| 网络断了 | 回退纯检索 | 功能不中断 |
| DeepSeek 额度用完 | 回退纯检索 | 同上 |

---

## 八、一句话总结

> **DeepSeek = 表达层，知识库 = 事实层。**
>
> 事实层决定「能不能答、答什么」，表达层只决定「怎么说得清楚」。
> 知识库没有的内容，系统会在调用 DeepSeek 之前就拒答——**不会瞎编**。
>
> 这也是为什么前面几轮我一直在补语料：**决定上限的始终是知识库，不是模型。**
