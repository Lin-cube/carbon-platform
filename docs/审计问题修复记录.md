## P0-1 碳排与声明因子不符 ✅ 已修复

**问题**：255,780 行碳排不等于 `(电+气)×0.5810`，43 栋建筑偏离，其中
`Moose_education_Omar` 零能耗却有 454,443 kg 碳排。看板碳排偏高 1.6%。

**修复**：
1. `db/fix/2026_11__carbon_recompute.sql`：先把待修行的原值备份到
   `fact_energy_hourly_carbon_bak`（255,780 行），再按因子重算 `carbon_kg`。
   **只改碳排一列，电量/燃气等原始能耗一行未动。**
2. 新增维护端点 `POST /api/system/maintenance/refresh-aggregates`（仅 admin），
   重算日/月/园区时/全局时四张聚合表 + 建筑评级。

**实测**：
| 项 | 修复前 | 修复后 |
|---|---|---|
| 2016 碳排合计 | 363,489,106.7 kg | **357,763,466.5 kg** |
| 与因子重算差 | +5,725,628.5 kg | +18.6 kg（逐行四舍五入） |
| 偏离行数 | 255,780 | **0** |
| 电量 | 614,125,847.9 kWh | 614,125,847.9 kWh（未变） |

回滚方式：`UPDATE fact_energy_hourly f JOIN fact_energy_hourly_carbon_bak b
USING (id, stat_year, stat_month) SET f.carbon_kg = b.old_carbon_kg;`

## P1-2 COP 两套口径 ✅ 已修复

**问题**：`/analytics/cop` 用简单平均（3.468），节能模拟用负荷加权（4.4089）。

**修复**：`selectCopSummary` 增加 `ΣE_hvac / Σ(E_hvac/COP)` 计算，`copAvg`
改取加权值；VO 新增 `copAvgMethod`（负荷加权/简单平均）与 `copAvgSimple` 对照字段。

**实测**：`copAvg=4.409 口径=负荷加权 简单平均=3.468` —— 与节能模拟 4.4089 一致。

## P1-3 流式响应终止不干净 ⚠️ 已缓解，未根治

**问题**：`curl: (18) transfer closed with outstanding read data remaining`。

**已做**：服务端在 `complete()` 前补发注释事件，改为 `finally` 收尾；
客户端以 `done` 事件为权威结束信号并主动 `reader.cancel()`（上一轮已修）。

**现状**：事件完整（`tool×1 + delta×189 + done×1`），HTTP 200，功能不受影响；
但 curl 仍报 (18)，说明 Tomcat 的 chunked 结束符未按预期发送。
**未根治**，如需彻底解决需改用 `StreamingResponseBody` 或换容器实现。
