### 4.2 碳排问题的证据

```sql
-- 43 栋建筑的碳排不遵循 0.5810 因子
SELECT COUNT(*) FROM (... HAVING ABS(f-0.581) > 0.01) → 43 栋 / 377,712 行 / 2,718 万 kg
```

极端个例：
```
Moose_education_Omar：电量 0 kWh、燃气 NULL、碳排 454,443 kg   ← 零能耗却有 454 吨碳
Panther_lodging_Kirk：实际因子 1.8474（应为 0.5810）
Panther_lodging_Kara：实际因子 1.4708
```

**来源**：这些行的 `import_batch_no` 全为 NULL，即**原始数据集**，不是本项目导入代码造成。
**影响**：看板碳排偏高 1.6%（约 5,726 吨 CO₂）。

### 4.3 已验证正确的部分

- 电量单位 kWh、EUI = 电量/面积、碳排因子常量 0.5810 在导入与工具中一致
- 异常率 4.74% 在 overview 与 analytics 两处一致
- 空值处理：`carbon_kg` 对 NULL 电量按 0 计（Java 侧显式处理）

### P1-1 详细证据（本轮最重要发现）

```
问：冷冻水供回水温差过小说明什么问题？
→ 路由：数据路径（未命中知识词表）
→ dataSource="无工具调用"、toolCalls=[]、citations=0
→ 但模型给出了 5 条详细原因（水流量偏大、换热效果差、负荷率偏低…）

同一问题直接问 RAG：
→ mode=llm+rag、citations=5、[来源：HVAC-002]，答案更准确且可溯源
```

**结论**：知识类问题可能**绕过 RAG**，产生无任何引用的模型自述答案。这正是「AI 引用是否对应真实证据」要防的情况。
