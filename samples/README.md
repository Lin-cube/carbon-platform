| `2017-08_能耗测试数据_3栋楼.csv` | 3 栋楼 × 2017-08 全月 × 24 小时 = **2,232 行** | 备选（2017-08 也是空月份） |

库中 2017-05 / 06 已有完整数据（各 33 万行、456 栋），导这两个月会走「按建筑+时间替换」，

**关于 2018-01 的异常基线**：
异常检测用「同一栋楼、同一星期几、同一时刻」过去 52 周的中位数做基线。
2018-01 可用历史是 2017-01 ~ 2017-09（约 28 周），少于理想的 52 周，
因此检出会略保守，但满足算法要求（≥2 个同槽位样本即可），能正常出结果。

## 导入步骤

1. 打开「数据导入」页 → 上传本文件
2. 系统应显示：**识别类型 = 能耗时序数据，2,232 行，12 列全部自动映射**（已实测通过，0 警告）
3. 清洗规则保持默认 → 预览 → 执行导入
4. 导入成功后，**务必把页面右上角的时间范围改成 `2018-01-01 ~ 2018-01-31`**
   （用 2017-08 文件则改成 `2017-08-01 ~ 2017-08-31`）

> ⚠️ 平台默认时间范围是 **2016-01-01 ~ 2016-12-31**。
> 不改时间范围，你会以为"导进去没数据"——其实是筛选条件没覆盖。

## 两个模板分别是什么

| 模板 | 作用 |
|---|---|
| **能耗数据模板** | 每行 = 一栋楼 + 一个时刻的读数。导入后进入 `fact_energy_hourly`，驱动看板、查询、分析、异常检测、AI 诊断。**必须含建筑编号 + 监测时间。** |
| **建筑台账模板** | 建筑的基础档案（面积、类型等），不带时间维度。**当前版本仅支持"识别"，不支持自动落库**，模板只作字段格式参考。 |

## 单位与格式

- 电量统一 **kWh**（MWh 请先换算）
- 时间：`2017-08-01 00:00:00` 或 `2017-08-01 00:00`
- 编码：UTF-8 或 GBK 均可（本文件带 BOM，Excel 打开不乱码）
- 单次上限：20 万行 / 100MB

### 11 条跳过明细

| 类型 | 条数 | 触发规则 | 界面提示 |

| 负值（-8.5） | 3 | 负值剔除 | 「能耗为负值，已按清洗规则剔除」 |

| 单位异常（0.05 vs 约 40，差 800 倍） | 2 | 单位一致性检查（≥300 倍） | 「疑似单位不一致（如 kWh 与 MWh 混用）」 |
